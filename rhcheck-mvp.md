# RH Check — план для Codex

Один файл. Читай его целиком. Не выходи за текущий этап, пока пользователь не написал «двигайся по плану» или не назвал этап.

Рабочее имя: **rhcheck**
Суть: вставил адрес токена на Robinhood Chain → через несколько секунд вердикт **don’t / thin / ok to size small** и три факта. Без кошелька. Без кнопки купить.

Сеть: Robinhood Chain (EVM L2, газ ETH). Контракты читать как обычный EVM.

## Продукт v0.1

Роут: `/0x…` или `/?token=0x…`

На странице только:

1. адрес, сеть, имя если есть
2. вердикт крупно: don’t / thin / ok to size small
3. три факта
4. блок + время снимка (UTC)
5. Copy link
6. мелкий дисклеймер: snapshot, not advice, not live tape

Три факта:

1. Права: mint / freeze / owner / fee-кошелёк — есть или нет, кто владеет
2. Пул: есть ли LP, грубая доля деплоера в пуле, если RPC отдаёт; иначе unknown
3. История деплоера: сколько контрактов с этого creator видно в нашей БД, сколько «мёртвых» по простому правилу

Под капотом с первого кода, даже если UI истории нет:

- таблица `snapshots(token, block, ts, raw_json, verdict, flags)`
- таблица `deployers(address, tokens_seen, dead_count, updated_at)`

Кеш ответа 30–60 секунд на адрес.

## Правила вердикта (`rules.md` + чистая функция)

Сначала if/else. Не ML.

**don’t** если верно любое:

- mint или freeze всё ещё у деплоера / owner
- owner не отрезан и может менять fee
- LP нет или деплоер явно контролирует пул так, что вывод читается из фактов
- этот деплоер уже помечен как серийный «мёртвый» по нашему правилу

**thin** если опасных прав нет (или unknown), но:

- пул тонкий / возраст пула минуты
- деплоер новый (нет истории)
- данных не хватает

**ok to size small** только если:

- опасные права сняты или заперты так, что это видно on-chain
- пул не пустой
- деплоер не серийный могильщик
- нет unknown по критическим флагам

Каждый вердикт логирует, какие флаги сработали. Фикстуры снимков → ожидаемый вердикт. Ложный ok хуже ложного don’t.

«Мёртвый» токен для статистики деплоера (простое правило v0.1): почти нет резервов или нет свопов за окно, которое зафиксируешь в `rules.md` (например 24h). Не угадывай объём с графика.

## Стек

- Next.js (App Router) + TypeScript
- один API route `GET /api/check?token=0x…`
- Postgres или SQLite на старте (лучше SQLite/libsql, чтобы каркас поднялся без облака)
- viem для RPC
- один RPC URL из `RH_RPC_URL`
- без лишних UI-библиотек; мобильный столбец, крупный вердикт, три строки

Переменные:

```
RH_RPC_URL=
RH_CHAIN_ID=
RH_EXPLORER_API_URL=   # опционально
```

## Этапы

Пользователь пишет «двигайся по плану» — делай **следующий несделанный этап целиком**, остановись, коротко скажи что готово и как проверить. Не прыгай через этап.

### Этап 0 — Каркас

- репозиторий Next.js + TS
- `.env.example`
- пустые модули: `lib/rpc.ts`, `lib/flags.ts`, `lib/pool.ts`, `lib/rules.ts`, `lib/db.ts`, `lib/check.ts`
- страница-заглушка: поле адреса + «not wired»
- README: что это, чего нет, как запустить `pnpm dev`
- не подключай реальный RPC, пока не начат этап 1

Критерий: `pnpm dev` открывается, адрес вводится, ответа сети нет.

### Этап 1 — Права контракта

- нормализация адреса, отказ на не-0x
- `eth_call` по стандартным кускам ERC-20 / Ownable / частому mint-freeze (не исполнять произвольный код)
- JSON: owner, mint, freeze, feeWallet, raw unknowns
- временный debug-роут или страница показывает сырой JSON прав

Критерий: на известном адресе с explorer сходятся owner / mint / freeze. Нет данных → поле `unknown`, не false.

### Этап 2 — Пул

- найти пару токена на известном семействе роутеров/фабрик, которые реально стоят на RH (не выдумывай адреса — вынеси в `lib/venues.ts` с комментарием «заполнить»)
- резервы, грубая доля деплоера, если holder LP читается
- если за день не находится пара: `pool: unknown`, вердикт не рисуй зелёным из-за этого

Критерий: хотя бы один реальный RH-токен с пулом даёт резервы; мусор без пары даёт unknown.

### Этап 3 — Правила и тесты

- `rules.md` человеческим языком
- `evaluate(snapshot) → { verdict, flags[] }`
- фикстуры в `tests/rules.fixtures.json` (don’t / thin / ok / unknown)
- тесты без сети

Критерий: все фикстуры зелёные. Нет фикстуры «ok при unknown mint».

### Этап 4 — Склейка check

- `lib/check.ts`: flags + pool + db deployer stats → snapshot → evaluate
- `GET /api/check`
- кеш 30–60с
- запись snapshot в БД даже если UI истории нет
- инкремент `deployers`

Критерий: один запрос = один JSON с verdict, facts[3], block, ts.

### Этап 5 — Страница результата

- `/0x…` или `/t/[address]`
- мобильный столбец, вердикт, три факта, блок/время, copy link
- дисклеймер
- без кошелька, инкогнито открывается
- состояния: loading / invalid / not found / ready

Критерий: шарится одна ссылка, на телефоне читается без зума.

### Этап 6 — OG и лимиты

- OG-картинка: вердикт + короткий адрес
- лимит на IP (грубый, in-memory ок)
- не светить RPC ошибками пользователю

Критерий: карточка ссылки в твите показывает вердикт.

### Этап 7 — Прогон на живых адресах

- скрипт или markdown `qa/addresses.md`: 20 адресов (мусор / серые / «нормальные на вид»)
- руками сверить 5 штук с explorer
- поправить пороги только в rules + фикстуры
- таблица ложных ok — цель ноль

Критерий: ноль ложных ok на прогоне. Unknown не стал ok.

### Этап 8 — Запись истории (ещё без алертов)

- список последних снимков одного токена в JSON-роуте `GET /api/history?token=`
- UI истории не обязателен
- без этого этапа нельзя честно делать алерты

Критерий: два check одного адреса в разное время = две строки snapshot.
